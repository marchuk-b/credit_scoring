# Кредитний скорінг

Система автоматичної оцінки кредитоспроможності: модель класифікує клієнта (**Poor / Standard / Good**), повертає скор 300–850, рішення та пояснення в реальному часі через Flask API і вебінтерфейс.

## Дані

Набір [Credit score classification](https://www.kaggle.com/datasets/parisrohan/credit-score-classification): `data/train.csv` (100 000 записів, 12 500 клієнтів × 8 місяців, мітка `Credit_Score`) і `data/test.csv` (50 000 записів без мітки; ті самі клієнти, інші місяці).

Дані «брудні»: значення на кшталт `40026.12_`, `__10000__`, `_______`, `!@9#%8`, вік −500 або 8698, рядки типу `22 Years and 1 Months`. Очищення виконує `src/data_processing.py`: сміття та значення поза допустимими діапазонами (`config.VALID_RANGES`) стають пропусками, які конвеєр заповнює сам. Ім'я, SSN та ID не використовуються як ознаки.

Усі розбиття (відкладена вибірка, крос-валідація) виконуються **за `Customer_ID`**, щоб записи одного клієнта не потрапляли одночасно в навчання й оцінку.

## Структура

```
app/            Flask: маршрути, валідація, шаблони, стилі
data/           train.csv, test.csv
models/         credit_model.joblib, report.json, cv_report.json (створюються при навчанні)
notebooks/      eda.ipynb — розвідувальний аналіз
src/            очищення, конвеєр, моделі, ансамбль, метрики, скоринг, звіт
tests/          тести очищення, API та сторінок
```

## Встановлення та запуск

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows;  Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

```bash
python -m src.train                 # крос-валідація кандидатів + навчання + оцінювання (кілька хвилин)
python -m src.train --no-cv         # без крос-валідації
python -m src.train --no-ensemble   # без ансамблю
python -m src.train --no-cv --no-ensemble   # швидкий запуск
python -m src.cv                    # лише крос-валідація (оновлює models/cv_report.json)
python -m app.main                  # вебзастосунок: http://127.0.0.1:5000
pytest -q                           # тести (потрібна навчена модель)
```

Після навчання в `models/` з'являються `credit_model.joblib` (найкраща за ROC-AUC модель і «типовий клієнт» для пояснень), `report.json` (дані для сторінок `/models` і `/dataset`) та `cv_report.json` (результати крос-валідації для сторінки `/models`).

## Моделі та метрики

Відкладена вибірка: 20 000 рядків (2 500 клієнтів, яких немає в навчанні).

| Модель | Accuracy | F1 macro | ROC-AUC | Gini (Poor) | KS (Poor) |
|---|---|---|---|---|---|
| Логістична регресія | 0,654 | 0,649 | 0,808 | 0,622 | 0,541 |
| **Gradient Boosting** | 0,689 | 0,683 | 0,847 | 0,725 | 0,613 |
| Ансамбль RF + LightGBM + XGBoost | 0,691 | 0,677 | 0,846 | 0,730 | 0,614 |

5-блочна крос-валідація за `Customer_ID` (ROC-AUC ± σ): логістична регресія 0,806 ± 0,005, Gradient Boosting 0,842 ± 0,004, Random Forest 0,845 ± 0,005, LightGBM 0,837 ± 0,005, XGBoost 0,826 ± 0,006. Таблиця також відображається на сторінці `/models` (читається з `models/cv_report.json`).

У роботі використовується Gradient Boosting: рівна з ансамблем якість за простішої та швидшої моделі. Ансамбль (`src/ensemble.py`) об'єднує RandomForest, LightGBM і XGBoost, а вага кожної моделі пропорційна (out-of-fold AUC − 0,5).

Скор = `300 + 550 · (P(Good) + 0,5 · P(Standard))`. Рішення: Good → «Схвалено», Standard → «На ручний розгляд», Poor → «Відмова».

## Пояснення рішення

Для кожного клієнта обчислюються наближені значення Шеплі (`src/predict.py`): рух від «типового клієнта» (медіани навчальної вибірки) до реального, по одній ознаці у випадковому порядку (16 перестановок). Результат — ознаки, що підвищили та знизили скор, із внеском у балах.

## Сторінки

- `/` — форма скорингу з результатом і поясненням;
- `/models` — порівняння моделей, крос-валідація, матриці помилок, ваги ансамблю, якість за класами, важливість ознак, розподіл скору;
- `/dataset` — статистика даних (класи, якість полів, особливості).

## API

`POST /api/score` — JSON із полями клієнта. Обов'язкові: `Age`, `Annual_Income`, `Outstanding_Debt`, `Delay_from_due_date`; решта 18 полів необов'язкові. Невідомі поля ігноруються, порожні значення та значення поза допустимими діапазонами вважаються відсутніми.

```json
{
  "score": 582,
  "class": "Standard",
  "decision": "На ручний розгляд",
  "probabilities": {"Good": 0.1226, "Poor": 0.0955, "Standard": 0.7819},
  "explanation": {
    "base_score": 547,
    "raise_score": [{"feature": "Delay_from_due_date", "label": "Середня затримка платежу",
                     "value": 10.0, "display": "10 дн.", "impact": 15.2}],
    "lower_score": [{"feature": "Num_of_Delayed_Payment", "label": "Кількість прострочених платежів",
                     "value": 5.0, "display": "5", "impact": -11.5}]
  }
}
```

Коди відповідей: 200 — успіх; 400 — не JSON-об'єкт або відсутні обов'язкові поля; 503 — модель ще не навчена. Також: `GET /health`, `GET /api/report` (404, якщо звіту немає).

Моделі та звіт зберігаються в іменованому томі `models`. Папка `models/` свідомо виключена з образу (`.dockerignore`), щоб навчена модель відповідала версіям бібліотек у контейнері.

## Обмеження

- Точність помірна (близько 69%): у 58% клієнтів мітка змінюється між місяцями, а модель оцінює окремий місячний запис.
- Ймовірності не калібровано: скор — це ранжування ризику, а не точна ймовірність дефолту.
- `Credit_Mix`, найімовірніше, відображає готову оцінку кредитного бюро, тому частина якості «успадкована» від неї.
- Набір даних може не відображати реального кредитного портфеля.
